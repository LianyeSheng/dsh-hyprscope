# 桌面标注会话（`hyprscope message annotate`）

[English](/docs/plugin/ANNOTATE.md) | 中文

`hyprscope message annotate` 是视觉 + 语音输入面：宿主冻结屏幕、圈出几处、按住键说话，agent 收到一条包含几何与话语的普通用户消息。本页是这个面的设计契约。它刻意不是第二份 wire format：会话目录、时间基准、文件形状和配对表以 [PROTOCOL.md](/docs/cli/PROTOCOL.zh.md) §11 为准，插件的工具、配置和降级叙述在 [DSH-PLUGIN.md](/docs/plugin/DSH-PLUGIN.zh.md)。本页确定的是所有权、由所有权推出的约束，以及实现必须守住的平台边界。

## 1. 定位与边界

这个面要消除一类请求里的歧义：“这个东西、这里、看起来不对”。只给截图，agent 只能猜用户指的是哪个像素；只给文字，位置又丢了。标注会话两者都带，但把它们分开：图保持干净，意图以数字传递。

| 面 | 拥有 | 从不做 |
|---|---|---|
| Quickshell 浮层 | 画冻结图、画形状、按住说话、审查卡、写会话文件 | 截屏、录音、转写、注入 prompt、改桌面状态 |
| DSH 插件 | 截屏、上下文、录音、转写、配对、意图卡、prompt 准入 | 画图、拿租约、改桌面状态、向别的窗口输入 |
| CLI | 启动浮层并写唯一一份请求文件 | 拥有会话、读麦克风、注入 |

浮层是一个“画图和写文件”的面。它从不拿租约、从不调用 `hyprctl`、从不录音、也从不截屏；它需要的一切要么已经在插件侧完成，要么已经写进 `session.json`。反过来，插件从不画一个像素、也从不决定形状：它只读浮层写下的几何并信任它。CLI 是其中最小的部分：`hyprscope message annotate` 启动那个单实例浮层，写一份带 `mode: "annotate"` 的 `open.json`，然后退出。会话里没有别的部分是 CLI 的事。

这也解释了为什么这个面不需要同意卡也能安全：它唯一改变的东西，是用户发给自己的 agent 的那条消息。它不加工具、不加权限，也不提供通往控制面的路径。

## 2. 单会话时钟

一个会话只有一个基准——它的 `t0`——和一个单位。

- `startedAt` 就是 `t0`：触发那一刻的绝对 epoch 毫秒。插件把它一次写进 `session.json`；之后每份文档都引用它，绝不重新定义它。
- 会话文档里的每个 `at`、`atStart` 和 `atEnd` 都是同一台机器时钟给出的绝对 epoch 毫秒；两个更早的例外 `open.json.at` 和桌面消息的 `ack.json.at` 仍是 ISO-8601 字符串。卡片显示时换算 `t = at - startedAt`，除此之外没有第二次换算。
- `audioStartedAt` 是录音第 0 个采样点的绝对时刻。录音器起不来时它是 `null`；没有语音的会话仍然是会话。
- 字节偏移是算出来的，从不落盘：16 kHz 单声道 s16le 正好每毫秒 32 字节，所以偏移是 `(at - audioStartedAt) × 32`，并夹到实际存在的字节范围内。

这条规则重要，是因为会话由三个进程共享——浮层、插件和只读 CLI。相对时间戳会让每个进程各加各的钟，几百毫秒的漂移就会悄悄改变一段话绑定到哪个标注。会话文档里的绝对时刻只留下一个换算点（卡片里的 `t`）和一个事实来源（`startedAt`）。

## 3. 只记几何，不录原始输入

标注记录是几何，不是指针的录像。

- 一个形状是 `rect`、`ellipse` 或 `arrow`，以截图自身图像像素的 `from`/`to` 保存，另带展示用的 `index`、时间区间和可选评论。
- 浮层写入时按监视器 scale 把屏幕坐标换成图像坐标，显示时再换回去；插件和 agent 只读图像像素。
- 形状指向的窗口，是用全局屏幕点对 `session.json.context` 里的窗口矩形做命中测试得到的；结果是可选的 `windowId`，永远不是必填项。
- 不记录指针轨迹、点击流、击键或任何原始输入事件。按住说话只用 Space，审查卡只用 Enter/Esc；这是这个面唯一观察的按键，它们也不进记录。
- 截图是不可变的证据。评论和形状只是元数据，从不烧进 PNG，所以 agent 可以裁剪、重读或对比图片，而标记不会遮住下面的像素。

用户的标记是权威意图，agent 据以行动的是几何。一句“这个按钮”仍然有歧义；一个矩形加一个窗口 id 没有。

## 4. 语音链路

语音连续录制、按短语转写，从不流式。

1. 录音器：插件以 16 kHz 单声道 s16le 参数拉起 `parec`，起不来退到 `arecord`；原始 PCM 写进 `audio.pcm`，`audioStartedAt` 记录第 0 个采样点。两个都起不来时，会话不带音频继续。
2. 按住说话：按住 Space 在 `voice-events.json` 里开一段；松开时用绝对的 `atStart` 和 `atEnd` 闭合这一段。浮层写段，插件从 PCM 里切段。
3. VAD：切出的每一段按 20 ms 帧打分；连续 300 ms 静音结束一个短语，有声部分不足 200 ms 的短语被丢弃，幸存短语两侧各补 200 ms，相邻短语均分共享间隙而不是重叠。
4. WAV：每个短语编码成规范的 RIFF/WAVE 文件，使用严格的 44 字节头，转写器不必猜格式。
5. 转写：每个短语单独交给 Host 的 `speechToText` 服务（当前 Host 里是 SenseVoice provider），带会话语言；调用是非流式的，上限 30 秒，结果——文字、时长、错误和短语边界——写进 `voice/<id>.json`。

转写发生在短语结束之后，而不是用户说话的同时；agent 看到的单位是短语，不是整段按住说话。这个选择来自审查卡：用户可以只改一个短语而不丢其余内容，一段话也可以分别描述两个不同标注。

## 5. 对齐规则

配对是带显式置信度的尽力解释，从不静默猜测。

| 规则 | 条件 | 置信度 | 来源 |
|---|---|---|---|
| 1 | 恰好一个标注与较短区间的重叠达到 60% | 0.9 | `overlap` |
| 2 | 多个标注重叠；取重叠最大者，并标记为有歧义 | 0.6 | `overlap` |
| 3 | 没有可用重叠，但短语的 anchor 指向一个存在的标注 | 0.8 | `anchor` |
| 4 | 否则，短语结束后 2 秒内开始且最近的标注 | 0.5 | `sequence` |
| 5 | 都不匹配 | — | 不绑定，按全局备注 |

表之上还有三条设计规则。阈值按较短区间计算，所以画一条长箭头时说的那句短短“这个”仍然能绑上。anchor 是刻意的兜底：它用按下按键那一刻用户选中或正在画的标注，能扛住开口前的停顿。审查卡里的手工改绑是权威的——提交的 `annotationId` 以置信度 1、来源 `manual` 覆盖自动结果，`null` 则把该短语变成全局备注。

歧义会被摆出来，而不是藏起来：有歧义的绑定在提交前就显示在审查卡里，用户可以改绑或者留作未绑定。agent 在卡片里看得到置信度和来源，因此可以发问，而不是替用户假设。

## 6. 干净图与意图卡

默认产物是一张干净截图加一张确定性的文本卡；标记只以文字存在。

- 卡片开头是计数，以及“截图是干净原图、以几何为准”的声明。
- 接着打印监视器、scale、指针、焦点窗口，以及按 z 序排列的可见窗口及其矩形。
- 每个标注带它的 `t` 区间、图像矩形、屏幕对应位置、命中窗口和评论；每段话带它的 `t` 区间、文字，以及绑定的标注或“未绑定，按全局备注理解”。
- 用户的总备注和最终编辑过的转写收尾。
- 干净 PNG 附在文字之后。卡片上限 8000 字符，图片上限 8 MiB；图片被跳过时卡片会说明，几何仍然完整。

卡片刻意做成确定性的：同一组会话文件必须永远产出同一条 prompt。它由插件根据提交的文件生成，不是模型生成、也不是浮层生成，所以 agent 的输入可复现、可审查。

## 7. 失败与降级

失败是局部的：缺少某个可选件只会收窄用户能做的事，从不损坏会话，也不阻塞还能走的路。

- 没有 Wayland 会话或没有 Quickshell：CLI 以 `NO_SESSION` 或 `OVERLAY_FAILED` 失败，并且不写请求。
- DSH 没运行：浮层直接说明，不打开会话；请求不会被悄悄排队。
- 没有 `parec` 也没有 `arecord`：`audioStartedAt` 保持 `null`，每条转写都带错误，手打评论仍然能交给 agent。
- 没有 `speechToText` 服务或转写失败：短语保留错误和空文字，审查卡请用户直接输入文字，提交不被阻塞。
- 截图超过 8 MiB 或读不出来：prompt 只带文字，卡片注明截图未附。
- 用户取消、浮层死亡或收到退出请求：插件停掉录音器、清理子进程、删除 `active.json`；不留下占用的麦克风，也不注入 prompt。

这些规则背后是同一条原则：会话目录是唯一的状态，不完整的会话可以通过读取现存文件来恢复。内存里不保留任何崩溃后会变得含糊的东西。

## 8. 上限

| 上限 | 值 | 原因 |
|---|---|---|
| 单段按住说话 | 60 秒 | 让一次切段、一趟 VAD 和审查卡都有界 |
| 附图 | 8 MiB | prompt 图片要落在 Host 的准入预算内 |
| 意图卡 | 8000 字符 | agent 必须完整读到几何，不能在模型上下文里被截断 |
| 上下文中的可见窗口 | 24 | 保持窗口列表可读；z 序和相交仍然能决定取舍 |
| 单次转写调用 | 30 秒 | provider 卡住不能把会话挂死 |

## 9. 跨平台适配器

只有把平台相关的部分命名出来，设计才是可移植的。适配器提供五种能力，别的都不提供：

| 能力 | 职责 |
|---|---|
| `capture` | 产出指针所在监视器的干净截图，并给出像素尺寸、布局矩形、scale、transform 和哈希 |
| `windows` | 报告焦点窗口，以及最多 24 个相交窗口的 z 序、矩形和工作区 |
| `recorder` | 开始和停止 16 kHz 单声道 s16le 原始 PCM，并报告第 0 个采样点的绝对时刻 |
| `overlay` | 启动一个浮层、把会话目录交给它，并能停止或探测它的死亡 |
| `hotkey` | 注册标注触发键，并报告用户看到的归一化按键 |

Phase 0 在 Linux/Hyprland 上实现全部五种：通过只读 CLI 的 Wayland 截屏、Hyprland 窗口元数据、`parec`/`arecord`、Quickshell 浮层，以及由 `hyprscope control install-bind` 安装的 compositor bind。适配器边界是设计义务，还不是一个独立的包：Hyprland 实现目前在内部满足这五个操作。

Phase 1 明确延后：

- 把适配器接口抽成独立模块，并配一致性测试；
- 非 Linux 的截屏和快捷键后端（X11、macOS、Windows），包括用 portal/PipeWire 截屏替代 compositor 专用截屏；
- 不依赖配置文件与 reload 的、与 compositor 无关的快捷键路径；
- Quickshell 之外的浮层工具包；
- 流式转写，以及在按住说话结束前就开始的转写路径；
- 跨多显示器拼接截屏、对窗口而不是对监视器标注，以及音频设备选择。

这些延后项都不改变会话契约：它们只是在同样的五种能力背后替换实现，文件、时钟、几何和配对规则保持原样。
