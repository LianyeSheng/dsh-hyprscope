# 观察与能力契约

[English](/docs/PROTOCOL.md) | 中文

这份文档固定 `hyprscope` 输出的字段含义，也记录控制面（`hyprscope control`）对外声明的能力边界。观察层的字段是 `dsh-cua` provider 的输入；改变桌面的能力只经 `hyprscope control` 暴露，不在只读命令里。

字段改名视为破坏性变更，需同步改测试和 README。

读命令接受 `--desktop user|agent|external`，用它选择要观察的实例；`user` 是默认值，省略时也取它。这个选择器不授予任何权限：观察仍然只读，默认的 user 解析会跳过 `desktop.json` 里记录的 agent 或 external 实例，所以正在运行的受管桌面不会悄悄变成用户的桌面。

## 1. 快照记录

`state --json` 的顶层：

| 字段 | 含义 |
|---|---|
| `readOnly` | 恒为 `true`。调用方可据此拒绝把该来源当成可执行后端 |
| `observedAt` | ISO-8601 采集时刻 |
| `session` | 发现结果：`instanceSignature`、`waylandDisplay`、`pid`、`runtimeDir`、`instanceCount`、`discovery`（`explicit`/`scan`）、`waylandDisplaySource`、`inheritedEnvironment` |
| `compositor` | `name`、`version`、`branch`、`configProvider`（`lua`/`hyprlang`）、`backend` |
| `isolation` | `mode: 'shared-seat'`、`seatCount`（仅 `doctor` 填充）、`note` |
| `active` | `window`、`workspace`、`monitor` |
| `monitors` / `workspaces` / `clients` / `layers` | 归一化数组 |
| `cursor` | `{ x, y }`，全局布局坐标 |
| `lock` | `{ locked: boolean \| null, source, sessionId, seat, type, reason? }` |

`clients[]` 的稳定字段：

```
windowId            Hyprland window address (0x…), the unique id for later operations
app                 window class
initialApp          class at startup
title               title (mutable, not an id)
pid                 client process
monitor             monitor id (number)
workspace           { id, name }, or null
position            { x, y }, global layout coordinates
size                { width, height }, logical pixels
floating            whether the window floats
fullscreen          internal fullscreen mode: 0 normal / 1 fullscreen / 2 maximized (a number, not a boolean)
fullscreenClient    client-side fullscreen mode, encoded like fullscreen
pinned / grouped    pinned / number of windows in the group
mapped / hidden / acceptsInput / xwayland
focusHistoryId      focus-history ordinal, 0 is the most recent
stableId            stable identifier generated by Hyprland
```

`monitors[]`：`id`、`name`、`position`、`size`（含 `scale`、`transform`、`refreshRate`）、`focused`、`dpmsOn`、`activeWorkspace`、`specialWorkspace`、`reserved`。
`workspaces[]`：`id`、`name`、`monitor`、`windows`、`hasFullscreen`、`lastWindow`、`lastWindowTitle`、`persistent`、`layout`。
`layers[]`：每个 surface 一条，`monitor`、`level`、`namespace`、`pid`、`position`、`size`、`alpha`。

## 2. 坐标与缩放

- 所有几何量都是**全局布局坐标**，原点在布局左上角；多显示器时可以是负数。
- `size` 是逻辑像素，不是物理像素：`scale = 2` 的 4K 输出逻辑尺寸是 1920×1080。
- 截图分辨率 = 输出物理像素。区域截图用全局布局坐标，`grim` 接受 `X,Y WxH`，本工具把 `x,y,w,h` 转成该格式。
- 监视器有 `transform`（旋转）时，区域坐标仍按布局坐标给，换算由 compositor 负责。
- 后续做指针输入时，必须用同一坐标系；不要用截图里的物理像素直接当布局坐标。

### 2.1 截图记录

`screenshot --json` 返回：

| 字段 | 含义 |
|---|---|
| `path` | 写出的 PNG 的绝对路径 |
| `bytes` / `width` / `height` | 文件大小与 PNG 的像素尺寸 |
| `sha256` | PNG 文件的 SHA-256 |
| `capturedAt` | ISO-8601 截取时间 |
| `source` | 截取来源：`{ monitor, region, scope, window }` |

`source.scope` 是 `layout`、`monitor`、`region` 或 `window`。窗口截图时 `source.window` 为 `{ identifier, appId, title }`，其中 `identifier` 是 compositor 报告的 foreign-toplevel 标识（Hyprland 用十六进制报告窗口的 stable id），`appId` 是窗口 class，`title` 是截取时的标题；`source.monitor` 和 `source.region` 为 null。其他 scope 下 `source.window` 为 null。

窗口截图从 `--window-id <0x… 地址或 foreign-toplevel 标识>`、`--window-app <class>`、`--window-title <精确标题>` 中恰好选一个，不能与 `--monitor` 或 `--region` 组合。`--window-app` 或 `--window-title` 有歧义时以退出码 2 结束，并列出每个候选的 `0x…` 地址、application id、工作区、标题，以及它位于当前活动工作区还是屏幕外，提示用 `--window-id` 指定一个。显式 `--output` 会在截取前预检：其目录必须已存在且可写，否则命令以 `SCREENSHOT_FAILED` 失败，并提示传 `--output <可写路径>`（默认缓存目录会先创建）。由 compositor 渲染这一个 toplevel，因此位于其他工作区、或者被别的窗口遮住的窗口也能截；只能截已映射的窗口，光标不会合成进图像，带 `no_screen_share` 规则或截图权限被拒绝的窗口会得到 compositor 的拒答占位图。这条路径需要原生 `bin/wl-capture` helper（`pnpm run build:capture`），以及提供 `ext-image-copy-capture`、`ext-foreign-toplevel-list` 和 `ext-image-capture-source` 的 compositor；helper 缺失时命令会提示去编译它。布局、监视器和区域截图仍然走 `grim`。窗口截图仍然只是只读观察：不涉及租约，也不涉及能力基线。

锁定会话的规则对所有 scope 不变：会话报告锁定时截图默认拒绝，传 `--allow-locked` 才放行。

## 3. 事件流

`.socket2.sock` 是行文本，格式 `event>>payload`，payload 为逗号分隔字段。`events` 只解析和透传：

```
workspace>>2
activewindow>>zen,Title
openwindow>>0x1234,2,zen,Title
closewindow>>0x1234
movewindow>>0x1234,2
monitoradded>>HDMI-A-1
```

`events` 命令把匹配串定义为 `event:data`（冒号），所以 `--match '^openwindow:'` 只匹配开窗事件。`--once` 在超时前没匹配到会以退出码 1 结束，便于脚本化等待。

## 4. 错误码

| 码 | 触发条件 | 调用方处理 |
|---|---|---|
| `USAGE` | 参数非法 | 修正参数，退出码 2 |
| `NO_SESSION` | 找不到实例 / 指定的 display 无 socket | 提示用户启动 compositor 或传 `--signature` |
| `SESSION_GONE` | 控制 socket 或事件 socket 已断开 | 重新发现，不要重试旧 handle |
| `READ_ONLY` | 请求了 allowlist 外的命令 | 编程错误，不要兜底 |
| `COMMAND_FAILED` | `hyprctl`/探针非零退出 | 看 `details.stderr`/`details.exitCode` |
| `BAD_OUTPUT` | 返回不是 JSON | 版本不兼容，记录 `details.sample` |
| `LOCKED` | 会话报告锁定且未 `--allow-locked` | 等解锁，不要重试截图 |
| `SCREENSHOT_FAILED` | `grim` 或窗口截图 helper（`bin/wl-capture`）失败、拿不到 PNG | 检查 `WAYLAND_DISPLAY` 与会话 |
| `TIMEOUT` | 超时 | 已发出的输入不可撤销（在 `hyprscope control run` 期间） |
| `CAPABILITY` | 计划（或一次批准请求）需要的能力未被已验收的基线授予，或者还没有验收基线 | 运行 `hyprscope control baseline --probe`（放宽时探针会请宿主在确认卡上确认），再重新规划；不要重试 |

## 5. 能力报告

`doctor --json` 的 `capabilities`：

```json
{
  "observation": ["screenshot", "events", "clients", "workspaces", "monitors", "layers", "cursor", "lockState"],
  "action": [],
  "wayland": {
    "seatCount": 1,
    "globals": [{ "interface": "zwp_virtual_keyboard_manager_v1", "version": 1 }],
    "capabilities": { "virtualKeyboard": true, "virtualPointer": true, "screencopy": true, "imageCopyCapture": true,
      "foreignToplevel": true, "workspaceManager": true, "idleNotifier": true, "sessionLock": true, "pointerWarp": true }
  }
}
```

`action` 恒为空，这是只读入口的承诺，不是待实现项：`hyprscope` 不改变桌面，控制能力只在 `hyprscope control`（§8、§9）里出现。`wayland` 为 `null` 表示探针未编译。

`doctor --json` 还带一个 `environment` 块，描述控制面需要的运行时；doctor 只看它，从不启动浮层、创建文件或写任何东西：

```json
{
  "environment": {
    "overlay": { "binary": "quickshell", "path": "/usr/bin/quickshell", "available": true, "source": "default", "hint": null },
    "state": { "path": "/home/user/.local/state/hyprscope", "exists": true, "writable": true, "probe": "/home/user/.local/state/hyprscope", "reason": null },
    "capture": { "window": "window capture asks the compositor for the toplevel (ext-foreign-toplevel-list), so it also works for a mapped window on an inactive workspace or off-screen; it does not need the window to be visible, and the PNG carries the window size, not the output size" }
  }
}
```

`overlay` 是同意浮层会启动的 Quickshell 二进制：`binary` 默认是 `quickshell`，除非 `HYPRSCOPE_QUICKSHELL` 覆盖它；`source` 说明来自 `default` 还是 `environment`；`available`/`path` 来自 PATH 查找；缺失时 `hint` 给出可执行的修复提示。`state` 是基线、租约和桌面记录共用的 `$XDG_STATE_HOME/hyprscope` 目录：`exists` 表示目录是否已存在，`writable`（`true`、`false`，无法判断时为 `null`）、`probe` 和 `reason` 说明能否在那里创建文件——在目录本身或最近的存在祖先上用 `access(W_OK)` 检查，不创建也不删除任何东西。`capture.window` 是窗口截取的一行语义：compositor 直接渲染 toplevel，所以位于其他工作区或被遮住（未显示在屏幕上）的已映射窗口也能截；PNG 是窗口尺寸，不是输出尺寸。人类可读报告会在 `environment` 标题下打印同样的事实。

### 5.1 能力基线

`doctor --json` 还会报告它观察的是哪个桌面，以及 `hyprscope control` 针对该桌面门控的能力基线（capability baseline，见 [COMPATIBILITY.md](/docs/COMPATIBILITY.zh.md) 和 [BASELINE.md](/docs/BASELINE.zh.md)）。`doctor` 只读已验收的文件：从不探测、不写文件、也不申请租约。

```json
{
  "target": { "kind": "agent", "signature": "…", "managed": true },
  "baseline": {
    "present": true,
    "state": "usable",
    "path": "/home/user/.local/state/hyprscope/desktop/baseline/<signature>.json",
    "approvedAt": "2026-11-17T23:12:00.000Z",
    "compositorVersion": "0.57.2",
    "target": "agent",
    "staleness": {
      "verdict": "fresh",
      "reasons": [],
      "measuredAt": "2026-11-18T00:05:00.000Z",
      "differences": []
    },
    "degraded": [],
    "missingRequired": [],
    "warnings": []
  }
}
```

`target` 是解析出的桌面：`kind` 是 `user`、`agent` 或 `external`，`signature` 是实时实例签名，`managed` 只有在桌面是记录在案的 agent 或 external 实例时才为 true。`baseline.target` 重复该基线所属的 kind。`baseline.staleness` 把基线与运行中的实例作比较：`verdict` 是 `fresh`、`stale` 或 `unverified`；`reasons` 是给人看的句子；`measuredAt` 是比较时刻；`differences[]` 用 `{ field, recorded, observed }` 列出不一致，值都是文本。没有已验收基线时 `staleness` 为 `null`。`stale` 表示记录的值不同，或者运行中的实例报不出该值；`unverified` 表示基线没有记录比较所需的值，包括在记录 effective 值之前写下的旧基线。

`present: false` 且 `state: null` 表示控制不可用，观察照常；这时 `warnings[0]` 给出读取方的理由（没有文件、还是草稿、读不了，或者 schema 更新）。`missingRequired` 列出基线没有测到的必需能力，`degraded` 列出缺失的安全路径；目前唯一的降级能力是 `safety.failsafe-bind`。这两个列表都不改 `capabilities.observation` 或 `capabilities.action`。

用户桌面保留按机器的 `baseline.json`；agent 或 external 桌面按实例签名放在 `desktop/baseline/<signature>.json`，所以一个桌面的基线门控不到另一个。这里的 `stale` 或 `unverified` 只是报告；`hyprscope control run` 会在任何同意步骤之前以 `CAPABILITY` 拒绝。

## 6. 与 `dsh-cua` 的映射

`dsh-cua` 的请求联合在 `packages/experimental/cua/src/protocol.ts`。"只读层"指 `hyprscope` 本身：下表只说明它能不能提供；控制侧已经能做的事情列在 §9，CUA provider 还没有对接。

| CUA 方法 | 只读层能否提供 | 说明 |
|---|---|---|
| `getCapabilities` | 部分 | 用 `doctor` 的平台/版本/isolation；`permissions` 来自租约状态（§8） |
| `listApps` / `findApps` | 可 | `clients[]` 的 `pid` + `.desktop` 文件可拼出 app 列表 |
| `listWindows` | 可 | `clients[]`，`windowId` 用 Hyprland 地址 |
| `activate` / `show` | 否 | 控制侧已可用 `focusWindow` / `workspace` 实现（§9） |
| `getState` | 部分 | 只有窗口几何与焦点；没有无障碍元素树（Wayland 无全局 AX，需 AT-SPI） |
| `getState` 的 `tree` / `elementId` | 否 | AT-SPI 是独立工作 |
| `screenshot` | 可 | 布局/监视器/区域走 `grim`，单个窗口走 `ext-image-copy-capture`，返回尺寸/sha256/路径 |
| `mouseMove` / `click` / `drag` / `scroll` | 否 | 控制侧已由 `wl-inject` 实现（§9） |
| `pressKey` / `typeText` / `paste` | 否 | 键盘注入已实现（§9）；剪贴板还没有 |
| `setValue` / `selectText` / `performAction` / `invoke` | 否 | 依赖 AT-SPI 元素树 |

映射时注意三点：

1. CUA 的坐标默认是"最近一次截图的像素"，`relative: true` 是 0–999 千分比；本工具给的是布局坐标。换算放在 provider，不要污染观察层。
2. CUA 的 `snapshotId`/`elementId` 没有对应物；窗口几何变化要用 `focusHistoryId` + `windowId` 自己判失效。
3. CUA 的 `appLevelAccessibility: false` 是 Linux provider 的诚实取值，别报 true。

## 7. 版本敏感点

- Hyprland 0.57 的 `dispatch` 参数是 **Lua 表达式**（例如 `hl.dsp.focus({ window = "address:0x…" })`），不是老的 dispatcher 名；`keyword` 在 Lua 配置下无效，配置变更走 `eval`。工具只支持 Lua provider：`configProvider` 不是 `lua` 时控制子集整体不可用（对应 [COMPATIBILITY.md](/docs/COMPATIBILITY.zh.md) 里的 `dispatch.lua`）。
- `hyprctl -j cursorpos` 在 0.57 返回 `{"x","y"}`；更老版本可能是纯文本 `x, y`，解析要容忍。
- `hyprland.lock` 的格式是 `<pid>\n<wayland-display>`；只读第一行也能工作，display 会退回扫描。
- 事件名会随版本增加（`ext_workspace_manager_v1` 相关、`screencopy` 等），消费者必须忽略未知事件而不是报错。
- 单窗口截图要求 compositor 提供 `ext-image-copy-capture`、`ext-foreign-toplevel-list` 和 `ext-image-capture-source`；Hyprland 0.57.2 提供。

## 8. 控制租约（`hyprscope control`）

租约解决的是**控制权归属**：谁在控制、什么时候结束。它本身不注入输入；注入与计划执行在 §9。观察层的 `readOnly`、`action: []` 语义因此不变：`hyprscope` 仍然不发任何改变桌面的命令，`doctor` 也不报控制或输入能力。

控制侧的状态看 `hyprscope control status --json`（`phase`、剩余时间、holder/overlay pid、恢复进度），记录格式见下方"租约记录"。

### 租约记录

唯一事实来源对用户桌面是 `$XDG_STATE_HOME/hyprlease/state.json`；agent 或 external 桌面把同样的记录放在 `$XDG_STATE_HOME/hyprlease/<signature>/state.json`，由内部环境变量 `HYPRSCOPE_LEASE_SIGNATURE` 选择。字段相同：

| 字段 | 含义 |
|---|---|
| `leaseId` | 不透明租约 id；所有 decision/control 记录都要带它 |
| `phase` | `consent` / `granted` / `released` / `denied` / `expired` / `revoked` |
| `reason` | 展示给宿主的申请理由 |
| `planBound` / `planSummary` | 租约是否批准了一份提交的计划，以及同意卡摘要；未绑定计划时为 `false` / `null` |
| `attempt` / `maxResumes` | 当前尝试（`0` 是原始计划，`1..maxResumes` 是恢复）与同意覆盖的恢复次数（默认 `1`，上限 `3`） |
| `totalBudgetMs` | 从 `createdAt` 起算的总预算，或 `null`（不限） |
| `renewals[]` | 每次续期一条 `{ at, attempt, ttlMs, expiresAt }`，按时间顺序 |
| `ttlMs` | 申请时请求的单次持有时间；续期只改 `expiresAt`，不改这个字段 |
| `consentDeadline` | 同意阶段截止；到期自动 `expired` |
| `grantedAt` / `expiresAt` | 批准时间与到期时间 |
| `endedAt` / `endReason` | 终态时间和原因（`agent` / `host` / `shortcut` / `ttl` / `stale-owner` / `consent-timeout`） |
| `requesterPid` / `holderPid` / `overlayPid` | 三个相关进程；holder 是批准后的持有者 |

心跳 `heartbeat.json` 每 500ms 由 requester/holder 刷新；超过 5 秒未刷新视为失主，下一次 `status` 或 `run` 会把租约收口成 `revoked`。

### 不变量

1. 单租约：`lease.lock` 以 `O_EXCL` 创建，第二次租约申请得到 `LEASE_ACTIVE`。
2. 终态不可逆：进入 `released/denied/expired/revoked` 后不再回到 `granted`。
3. 记录归属：`decision.json` / `control.json` 带 `leaseId`，不属于当前租约的记录被忽略。
4. 输入不重放：交还之后排队中的动作一律不执行；已发出的输入不可撤销（注入启用后成立）。
5. 强制收口：`panic` 在 5 秒内没等到 holder 收口，就自己停浮层、写终态、放锁。
6. 续期不重新征求同意：`renewLease` 只续 `granted`、未过期、同一 `leaseId` 的租约，`attempt` 每次加一且不超过 `maxResumes`，`planBound` 和 `planSummary` 不变（细节见 `docs/LEASE.md`）。

### 兜底快捷键

`hyprscope control install-bind` 在 `~/.config/hypr/hyprland.lua` 追加带标记的块，里面有三处 `hl.bind(...)`。兜底 bind 的参数是 `hl.dsp.exec_cmd("<绝对路径 node> <绝对路径 bin/hyprscope.ts> control panic --source shortcut")`，并带 `description = "hyprscope failsafe: revoke desktop control"`。桌面消息 bind（默认 `SUPER + ALT + M`，可用 `--message-key` 改）运行 `hyprscope message open`，带 `description = "hyprscope message: open the desktop composer"`。桌面标注 bind（默认 `SUPER + ALT + A`，可用 `--annotate-key` 改）运行 `hyprscope message annotate`，带 `description = "hyprscope: desktop annotate"`。安装流程：先检查三个键互不相同且都没被占用 → 备份配置 → 写块 → `hyprctl reload` → 用 `hyprctl binds -j` 的 `description` 验证三处 → 把消息键和标注键记进消息状态目录（`shortcut.txt`、`annotate-shortcut.txt`）→ 任一步失败都恢复备份与两份快捷键记录、删掉生成的 Lua 文件，并报 `BIND_FAILED`。

绑定的键名要写成 Hyprland 的拼写（`Escape` 而不是 `ESC`）；`hl.bind` 在 0.57 里记录的 `arg` 是内部索引而不是命令字符串，所以验证只能看 `description`。

### 与 CUA 的关系

CUA 的 `click` / `typeText` 等方法仍然没有实现，`getCapabilities().action` 不应把它们报成可用。将来注入 helper 的前置条件是：每次批量动作前读取租约，`phase === "granted"` 且 `leaseId` 匹配才继续；租约终态后拒绝一切注入。

## 9. 计划执行（能力声明）

`hyprscope` 仍然只读。改变桌面状态的唯一命令是 `hyprscope control run <plan.json | ->`：它必须持有 §8 的一份绑定了提交计划（`planBound: true`）的租约。`hyprscope control install-bind` 只写 Hyprland 配置文件，不改变桌面状态；`hyprscope message` 面只画浮层、写消息与标注会话文件，同样不是控制路径。

计划执行、干扰询问、恢复模型和 fault 记录见 `docs/PLAN.md`；换机器、换版本之后这些能力还成不成立，见 [COMPATIBILITY.md](/docs/COMPATIBILITY.zh.md)（能力基线，已实现并在运行时生效）。

新增能力面：

| 能力 | Wayland 协议 / 接口 | 备注 |
|---|---|---|
| 指针绝对/相对移动 | `zwlr_virtual_pointer_manager_v1` → `motion_absolute` / `motion` | 单 seat，与物理指针交错 |
| 指针按键 | 同一 manager → `button` | 绝对坐标点击是低置信动作 |
| 滚动 | 同一 manager → `axis` + `frame` | 值以 `wl_fixed` 计 |
| 键盘按键与文本 | `zwp_virtual_keyboard_manager_v1` → `keymap` / `key` / `modifiers` | 固定 US keymap，键码为 evdev |
| 焦点 / 工作区切换 | `hyprctl dispatch '<lua 表达式>'` | 测试机的 compositor 用 Lua 配置 provider，`dispatch` 的参数按 Lua 求值；只执行执行器生成的白名单子集：`hl.dsp.focus({ workspace = … })` / `hl.dsp.focus({ window = … })` |
| 窗口移动 / 尺寸 | 同一子集：`hl.dsp.window.move` / `hl.dsp.window.resize` | 绝对布局坐标（`x`/`y`，调整尺寸时 `x`/`y` 是宽高）；表达式不带 `relative` 字段——Lua API 里 `relative` 缺省即绝对，工具从不生成相对移动；窗口处于全屏时 compositor 拒绝这两个调用 |
| 窗口浮动 / pin | 同一子集：`hl.dsp.window.float` / `hl.dsp.window.pin` | 显式设状态：`action = "on" \| "off"`，不是 toggle |
| 窗口全屏状态 | 同一子集：`hl.dsp.window.fullscreen_state` | `internal` / `client` 各取 `0`（普通）/ `1`（全屏）/ `2`（最大化），`action = "set"` |
| 静默移到工作区 | 同一子集：`hl.dsp.window.move` + `follow = false` | `follow = false` 不切换当前工作区；这是 dispatcher 子集的能力，计划 op 目前没有对应项 |

计划 op `resizeWindow`（绝对 `width`/`height`）和 `fullscreenWindow`（`internal`/`client` 模式）分别映射到窗口尺寸与全屏状态这两类调用；`floatWindow` 的 `floating`/`pinned` 映射成显式 `on`/`off`。

注入 helper 还要求租约证明：`--lease-state <state.json> --lease <id>`，每次注入前重读状态文件，`phase` 不是 `granted`、id 不匹配、租约没有批准具体计划（`planBound` 不为 `true`）或已过期就拒绝执行该条命令；`--probe` 和 `--dry-run` 不受影响。

Lua 表达式由执行器按白名单模板拼接，变量先过格式校验（窗口地址 `0x…`、工作区名 `[A-Za-z0-9._-]`、坐标为整数），不做字符串透传；compositor 返回 `error:` 或 `warning:` 都按失败处理。

明确不提供：`exec`、`keyword`、`kill`、`plugin`、任意 dispatcher、任意 Lua、shell 命令、配置修改。唯一的 `hyprctl reload` 在 `install-bind` 里，只用于让受管快捷键生效。

计划记录（`out/runs/<runId>/`）不是观察契约的一部分，字段随执行器演进；只有 `docs/PLAN.md` 里列出的 fault 记录字段对调用方有稳定性承诺。
## 10. 桌面消息面（`hyprscope message`）

`hyprscope message` 既不是观察也不是控制：它负责提示条/输入浮层，以及运行中的 DSH Host 读取的那些文件。它不拿租约、不改桌面状态，也不贡献任何观察字段。

`open`（`--json`）返回 `{ command: "open", dir, overlay: { pid, log }, request: { nonce, at }, dsh: "available" | "unavailable" }`；`annotate` 返回同样的形状，`command: "annotate"`，`request.mode: "annotate"`；`overlay` 返回 `{ command: "overlay", dir, overlay }`；`stop` 返回 `{ command: "stop", dir }`。`--lang zh|en` 选择这条命令启动的浮层语言（默认 `zh`，或 `HYPRSCOPE_LANG`）。文件在 `$XDG_STATE_HOME/hyprscope/message`（或 `HYPRSCOPE_MESSAGE_DIR`）：Host 写 `status.json`、`ack.json`、`last-session.json` 和 `overlay.log`；CLI 写 `open.json` 和 `quit.json`；`hyprscope control install-bind` 把消息键和标注键记进 `shortcut.txt` 与 `annotate-shortcut.txt`；浮层把每条消息写成 `outbox/` 里的一份 JSON 文档。浮层是用 `-n` 启动的 Quickshell 进程，重复调用也只保留一个实例；没有 compositor 是 `NO_SESSION`，没有 Quickshell 是 `OVERLAY_FAILED`。标注请求有自己的一套会话文件，见 §11。插件那一半和注入消息的形状见 [docs/DSH-PLUGIN.zh.md](/docs/DSH-PLUGIN.zh.md)。

## 11. 桌面标注会话（`hyprscope message annotate`）

`hyprscope message annotate` 向运行中的 DSH Host 请求一次桌面标注会话：冻结截图、手绘形状、按住说话的语音，以及一张简短的审查卡。CLI 启动与输入框相同的单实例 Quickshell 浮层，并写一份带 `mode: "annotate"` 的 `open.json` 请求；不带 `mode` 的请求仍然是旧的输入框请求。会话归插件所有：它通过只读 CLI 截屏、录麦克风、逐段转写，最后注入一条用户消息。CLI 不写会话文件、不拿租约；标注浮层也不改变桌面状态。

### 11.1 会话目录与文件

插件创建 `<messageDir>/annotate/<sessionId>/`，其中 `messageDir` 是桌面消息目录（`$XDG_STATE_HOME/hyprscope/message`，可用 `HYPRSCOPE_MESSAGE_DIR` 覆盖）。`sessionId` 是触发时刻的紧凑 UTC 串加四位随机十六进制，例如 `20261119T162512345Z-a1b2`。

| 文件 | 写入方 | 用途 |
|---|---|---|
| `session.json` | 插件 | 会话记录：`version`、`sessionId`、`mode: "annotate"`、`startedAt`、`audioStartedAt`、`state`（`ready` 表示浮层可以开始，之后是 `sent` 或 `cancelled`）、`language`、`capture`、`context`、`error` |
| `capture.png` | 插件 | 被截监视器的干净截图；同一路径也在 `session.json.capture.path` 里 |
| `audio.pcm` | 插件 | 原始麦克风录音：16 kHz、单声道、有符号 16 位小端，每毫秒 32 字节 |
| `voice-events.json` | 浮层 | 按住说话的语音段，带绝对起止时间和可选的 `anchor` |
| `voice/<id>.json` | 插件 | 单段转写：`id`、`text`、`seconds`、`error` 和可选的 `phrases[]` |
| `annotations.json` | 浮层 | 标注几何与评论，每次变化都重写 |
| `send.json` | 浮层 | 最终提交：`overallNote`、`items[]` 和 `segments[]` |
| `ack.json` | 插件 | 注入回执：`ok`、`message`、`sessionId` 和 `at` |
| `cancel.json` | 浮层 | `{ version: 1, at }`；可选，用户取消时写入 |
| `error.json` | 插件 | `{ version: 1, message, at }`；可选，会话无法继续时写入 |

`active.json` 放在 `<messageDir>/annotate/active.json`，不在会话目录里：它是浮层加载时轮询的入口，带 `{ version, sessionId, dir, startedAt, audioStartedAt, state }`。会话结束时插件把它删掉，所以残留的入口不会重新打开一个崩掉的会话。

除 `voice/<id>.json` 外，每份文档都带 `version: 1`；版本或形状校验不过的文档，插件和浮层都当作不存在。

### 11.2 时间基准

一个会话只有一个基准：`startedAt`，也就是触发那一刻的绝对 epoch 毫秒。`annotations.json`、`voice-events.json`、`voice/<id>.json` 和 `send.json` 里的每个 `at`、`atStart`、`atEnd` 都是同一台机器时钟给出的绝对 epoch 毫秒；卡片展示 `t = at - startedAt`。磁盘上不写相对时间戳，所以浮层、插件和 CLI 不会各走一套钟。

`audioStartedAt` 是第一个 PCM 采样的绝对时刻，录音器起不来时为 `null`。切音频时插件按录音起点换算偏移（`at - audioStartedAt`）；16 kHz 单声道 s16le 正好每毫秒 32 字节，所以字节偏移 = 毫秒 × 32。每次切分都会夹到实际存在的字节范围内。

有两份文档保留旧形状：`open.json.at` 是 ISO-8601 字符串，桌面消息的 `ack.json.at` 也是 ISO-8601 字符串。标注 `ack.json.at` 是 epoch 毫秒，因为标注文档都用同一个时钟。

### 11.3 图像、屏幕坐标与归一化

`session.json.capture` 描述干净截图：`path`（PNG 绝对路径）、`width`/`height`（图像物理像素）、`layoutRect`（Hyprland 全局布局坐标下的 `[x, y, width, height]`）、`monitor`、`scale`、`transform` 和 `sha256`。插件用只读的 `screenshot --monitor` 截取指针所在监视器（取不到时用聚焦的监视器）。

PNG 上从不作画：形状和评论只作为元数据存在。`annotations[].from` 和 `to` 是 PNG 自身像素坐标，原点在图像左上角。浮层显示时按 `scale` 归一化（除以 `scale`，图像按 `width / scale` × `height / scale` 绘制），写文件时再换算回去。因此屏幕点 = `layoutRect` 原点 + 图像坐标 / `scale`；意图卡两种形式都会打印。`windowId` 是用这个全局点对 `context.windows[].rect`（全局布局坐标）做命中测试得到的。

`session.json.context` 带 `cursor`（全局布局点或 null）、`focusedWindow`（窗口地址或 null）、`windows[]`（与截图相交的窗口，最多 24 个，按 z 序，越靠后越在上）和 `monitors[]`。窗口记录是 `{ id, class, title, pid, rect, workspace, monitor, focused, floating }`；`id` 是 Hyprland 地址，标题和 class 只是可变元数据，不是标识。

### 11.4 标注记录

`annotations.json.items[]` 每个形状一条记录：`id`、`index`（从 1 开始的显示编号，列表重排时重新编号）、`shape`（`rect`、`ellipse` 或 `arrow`）、`from`、`to`、`atStart`、`atEnd`、`comment`，以及命中测试得到的可选 `windowId`。评论留在文件和卡片里，不会烧进图片。浮层每次变化都原子重写这份文档，所以崩溃不会留下半份 JSON。

### 11.5 语音段与 VAD 短语

`voice-events.json.segments[]` 每段按住说话一条记录：`id`（`v1`、`v2`、……）、`atStart`、`atEnd`，以及可选的 `anchor`（`{ x, y, windowId?, annotationId? }`），也就是按下按键那一刻的指针位置和选中或正在画的标注。开始录音时浮层先写一段（结束等于开始），停止时再重写。

插件为整个会话录原始 PCM，然后切出每一段，在段内跑帧能量 VAD：20 ms 一帧，连续 300 ms 静音结束一个短语，有声部分不足 200 ms 的短语丢弃，每个短语两侧各补 200 ms（相邻短语劈开共享的静音间隙，而不是重叠）。每个保留下来的短语单独转写；`voice/<id>.json` 存该段拼接后的 `text`、`seconds`、`error`，以及绝对时间的 `phrases[]`，每项是 `{ atStart, atEnd, text }`。

配对粒度是短语，不是整段按住说话：一段可以切出多个短语，分别绑定不同标注。DSH 的 `speechToText` 服务缺失或转写失败时，文件带 `error`、`text` 为空；浮层显示失败，用户可以在审查卡里直接输入文字。转写失败不会阻塞提交。

### 11.6 绑定与置信度

插件把短语和标注配对（`linkVoiceToAnnotations`），每条配对形如 `{ annotationIds, voiceIds, confidence, source, ambiguous }`：

| 规则 | 条件 | 置信度 | `source` |
|---|---|---|---|
| 1 | 唯一一个重叠标注覆盖较短区间的 60% | 0.9 | `overlap` |
| 2 | 多个标注重叠；取重叠最大者，并标记为有歧义 | 0.6 | `overlap` |
| 3 | 没有可用的重叠，但该段的 `anchor.annotationId` 指向已存在的标注 | 0.8 | `anchor` |
| 4 | 否则，取短语结束后 2 秒内开始且最近的标注 | 0.5 | `sequence` |
| 5 | 都不匹配 | — | 不绑定；该短语按全局备注处理 |

低于 60% 的部分重叠不算可靠的时间匹配，会落到规则 3 和 4。多个短语可以绑定同一个标注，并保留时间顺序。文字 `comment` 和绑定上的语音都会保留，互不覆盖。审查卡里的改绑是权威的：显式写出的 `send.json.segments[].annotationId` 会以置信度 1、来源 `manual` 替换该段所有短语的自动配对；写 `null` 则去掉配对，把该段当作全局备注。

### 11.7 提交、回执与降级

提交时浮层写 `send.json`，带 `version`、`sessionId`、`at`（epoch 毫秒）、`overallNote`、最终的 `items[]` 和 `segments[]`。每段的 `text` 是用户最终的文字：只有一个 VAD 短语的段，它会替换转写；转写失败的段会变成一条手打短语；有多个短语的段仍使用 `voice/<id>.json` 里的逐短语文本，因为那才是配对粒度。插件最多等 6 秒转写队列，应用提交的文字和绑定，组装意图卡，再通过 DSH Host 注入一条 prompt。

成功时写 `ack.json`：`ok: true`、收到 prompt 的 DSH `sessionId`、`message: null`（图片没能附上时是 `"sent without the screenshot"`）；浮层 1.5 秒后关闭。失败时写 `ok: false` 和错误文本；浮层显示错误并保留标注与转写，用户可以重试或返回。`error.json` 是不可重试的路径——会话没能准备好——浮层只提供关闭。

降级都是局部的，会话仍然可用：

- 没有 Wayland 会话或没有 Quickshell：`hyprscope message annotate` 以 `NO_SESSION` 或 `OVERLAY_FAILED` 失败，不写请求。
- DSH 不在运行（心跳过期）：命令仍启动浮层并报告 `dsh: "unavailable"`；浮层提示 DSH 未运行，不开会话。
- `parec` 和 `arecord` 都没有：`audioStartedAt` 为 `null`，每段转写都带错误，会话以文字评论继续。
- 没有 DSH `speechToText` 服务或转写失败：走同一套 `voice/<id>.json` 错误路径；不阻塞发送。
- 截图超过 8 MiB 或读不出来：prompt 只带文字，卡片里注明截图未附。
- 用户取消（`cancel.json`）、浮层崩溃或收到退出请求：插件停录音、清理子进程并删掉 `active.json`；不留下麦克风占用，也不注入任何 prompt。

### 11.8 浮层状态

浮层按 `loading → annotating → review → sending → sent | error | cancelled` 迁移。`loading` 阶段轮询 `active.json` 和 `session.json`，DSH 5 秒内没准备好就失败。`annotating` 显示冻结图、形状工具条、编号、按住说话提示和可选的评论编辑框；Space 开始和停止按住说话，Enter 进入 `review`，Esc 弹出取消确认。`review` 里卡片列出标注和转写，可以改文字、改绑某一段；Enter 提交，Esc 回到 `annotating`。`sending` 轮询 `ack.json` 并在 20 秒后超时；`sent` 在收到回执 1.5 秒后关闭，任何失败都落到 `error`。浮层在 `loading` 阶段隐藏，避免插件截的冻结图里出现浮层；只有可见时才独占键盘。
